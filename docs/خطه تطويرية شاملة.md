### 1.1 الدوافع الهندسية وفلسفة التحول إلى نظام معرفي ذاتي الشفاء

في الأنظمة البرمجية التقليدية متعددة الوكلاء (Multi-Agent Orchestrators)، يتم التعامل مع الأخطاء كاستثناءات متأخرة بعد وقوع الكارثة (Reactive Post-Mortem Exceptions):
- عندما يستنفد نموذج الذكاء الاصطناعي ميزانية التوكنز، يتوقف النظام قسرياً مسبباً هدراً مالياً.
- عندما يقع خطأ في سياق الكود أو يكتب المطور التوليدي استيراداً معطوباً (Broken Import)، تفشل دورة الاختبارات كاملة وتتكرر المحاولات العمياء (Brute-force Trial and Error).
- عندما تتعرض واجهات برمجة التطبيقات السحابية (Cloud LLM Gateways) لاختناقات في الحصص اليومية (Rate Limits / 429 Quotas / 503 Outages)، ينهار خط الأنابيب البرمجي بدون مسار بديل متكيف.

**الفكرة الثورية المطروحة:**
تأسيس **عميل رقابي معرفي داخلي فائق الذكاء (Autonomous Cognitive Sentinel & SRE Agent)** مدمج في صلب محرك التشغيل. لا يعمل هذا العميل كمجرد "معالج أخطاء" (Error Handler)، بل كـ **"عقل واعي موازٍ" (Parallel Cognitive Arbiter)** يراقب كل استدعاء، كل متغير، كل دورة تنفيذية، وكل استجابة سحابية، ويتدخل استباقياً لمنع الفشل وتحويل النظام إلى بيئة برمجية ذات مناعة فائقة وذكاء خارق.

### 1.2 نموذج حلقة المراقبة والتحكم الاستباقي المعرفي (OODA Loop)

يعمل العميل الرقابي الداخلي عبر حلقة معرفية مغلقة ومستمرة عبر 5 أطوار متزامنة:
1. **الرصد اللحظي (Observe):** التقاط كافة الانحرافات اللحظية (AST Syntax Drift، استهلاك الذاكرة، أزمنة استجابة السحابة، مؤشرات تكلفة التوكنز، واستدعاءات الطرفية المشبوهة).
2. **التوجيه والتحليل السياقي (Orient):** تحليل الأثر المتبادل عبر ربط الخطأ برسم العلاقات المعمارية المولد بواسطة `Graft` وسجل الذاكرة التاريخي (`ConversationMemoryStore`).
3. **اتخاذ القرار الحسابي (Decide):** تقييم الخيارات المتاحة (هل يتم تصحيح الكود موضعياً؟ هل يتم تغيير موجه الـ Prompt؟ هل يتم تفعيل قاطع الدائرة والتبديل لمزود سحابي بديل؟).
4. **التنفيذ التصحيحي الآمن (Act):** حقن التعديلات التصحيحية داخل صندوق الرمل الآمن (Sandbox Isolation) وإعادة تقييم الحالة بدون التأثير على سير العمل للمستخدم.
5. **التأمل والتعلم التراكمي (Reflect):** توثيق سبب الخطأ واستراتيجية التعافي الناجحة داخل قاعدة المعرفة الداخلية لتفادي الوقوع في نفس الخطأ مستقبلاً.

### 2.1 العقد الهيكلي والواجهات البرمجية للعميل الرقابي (`CognitiveSentinelAgent`)

يمثل العميل الرقابي كائناً برمجياً مستقلاً ذو صلاحيات عليا (Supervisory Agent)، يتمتع بالقدرة على حقن السياسات، واعتراض الإشارات عبر خطوط الأنابيب، والتعديل الديناميكي على معطيات الوكلاء الآخرين.

```python
"""Cognitive Sentinel & Autonomous SRE Interface Contracts."""

from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from enum import Enum
from pathlib import Path
from typing import Any, Callable, Dict, List, Optional, Tuple

class IncidentSeverity(str, Enum):
    LOW = "LOW"
    MEDIUM = "MEDIUM"
    HIGH = "HIGH"
    CRITICAL = "CRITICAL"
    FATAL = "FATAL"

class InterventionAction(str, Enum):
    PASS_THROUGH = "PASS_THROUGH"
    AUTO_PATCH_CODE = "AUTO_PATCH_CODE"
    MUTATE_PROMPT = "MUTATE_PROMPT"
    SWITCH_CLOUD_PROVIDER = "SWITCH_CLOUD_PROVIDER"
    THROTTLE_TOKENS = "THROTTLE_TOKENS"
    ROLLBACK_WORKSPACE = "ROLLBACK_WORKSPACE"
    ESCALATE_TO_HUMAN = "ESCALATE_TO_HUMAN"

@dataclass
class CognitiveIncident:
    """Detailed metadata for an intercepted runtime or cloud anomaly."""
    incident_id: str
    severity: IncidentSeverity
    origin_module: str
    target_role: str
    error_signature: str
    raw_payload: Any
    suggested_action: InterventionAction
    auto_healed: bool = False
    remedy_description: str = ""
    timestamp_epoch: float = 0.0

class ICognitiveSentinel(ABC):
    """Formal protocol for the internal AI supervisor and cloud auditor."""

    @abstractmethod
    def intercept_ast_mutation(self, file_path: Path, new_code: str) -> Tuple[bool, str, Optional[str]]:
        """Audits AST before disk write; returns (is_safe, error_msg, auto_healed_code)."""
        pass

    @abstractmethod
    def intercept_cloud_call(self, provider: str, model: str, prompt_tokens: int) -> Tuple[bool, str, Optional[str]]:
        """Pre-evaluates cloud quota and cost ceilings; returns (can_proceed, reason, fallback_model)."""
        pass

    @abstractmethod
    def handle_runtime_error(self, exc: Exception, context: Dict[str, Any]) -> CognitiveIncident:
        """Autonomously decodes runtime errors and synthesizes immediate self-healing actions."""
        pass

    @abstractmethod
    def evaluate_investigation_drift(self, role: str, steps: int, tokens_burned: int, edits_done: int) -> bool:
        """Detects cognitive loops and triggers proactive prompt redirection."""
        pass
```

## 3.5 حزمة مسارات التنفيذ وخطوط الأنابيب (`orchestrator/pipeline/`)

```
┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│                               PIPELINE COGNITIVE SUPERVISION FLOW                                      │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                                        │
│   BasePipeline._setup_run() ───► PreFlightGuard (Zero-Token Static AST & Imports)                     │
│               │                                │                                                       │
│               ▼                                ▼ (Pass)                                                │
│   DynamicTokenGovernor ────────► DevTestLoop / FullPipeline Iteration                                  │
│               │                                │                                                       │
│               │ (Token / Loop Monitor)         ▼                                                       │
│   Sentinel Circuit Breaker ────► Tester / Reviewer Verification                                        │
│               │                                │                                                       │
│               │ (Auto-Heal if Failed)          ▼ (All Green)                                           │
│   Cloud Failover Mesh ─────────► GitOps Commit & Telemetry Finalization                                │
│                                                                                                        │
└────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 21. `orchestrator/pipeline/__init__.py`
- **الدور الحالي:** تصدير خطوط الأنابيب البرمجية (`BasePipeline`, `DevTestLoop`, `FullPipeline`, `AuditPipeline`, `AuditFixPipeline`, `DocumentationPipeline`, `PipelineStateMachine`, `PipelineCheckpoint`).
- **الاندماج المعرفي للعميل الرقابي:** تصدير المحرك الموحد `SentinelSupervisedPipelineRunner`.

### 22. `orchestrator/pipeline/base_pipeline.py`
- **الدور الحالي:** يمثل العمود الفقري لجميع خطوط الأنابيب؛ يدير عزل فروع Git، تهيئة السجلات، إدارة الذاكرة، مراقبة التوكنز والمهلات الزمنية عبر خيوط المعالجة المتزامنة (`Thread Monitor`)، وإدارة دورة حياة المحادثات (`_run_conv`).
- **المتغيرات والدوال:**
  - `class ConvRunResult`: نتيجة تشغيل المحادثة.
  - `_setup_run()`: تهيئة الفروع، السجلات، والسياق المعماري.
  - `_run_conv()`: تشغيل محادثة الوكيل مع مراقبة التوكنز والمهلة الزمنية وقواطع الدوائر.
  - `_run_preflight()`: فحص الشفرة النحوية قبل استدعاء الوكلاء.
  - `_execute_tests()`: تشغيل الاختبارات عبر المحول الخاص بلغة المشروع.
  - `_finalize_pipeline()`: حفظ التقارير وعمل Commit وتخزين الذاكرة.
- **الاندماج المعرفي للعميل الرقابي:**
  - تحويل `_run_conv` إلى حلقة معرفية تفاعلية: عند حدوث خطأ 429 أو `QuotaExhausted`، يقوم العميل الرقابي تلقائياً بتبديل كائن الـ `LLM` داخل كائن الـ `Conversation` إلى المزود السحابي التالي في سلسلة الـ Failover واستئناف التنفيذ من نفس النقطة بدون فقدان سياق المحادثة وبدون إعادة تشغيل الخط من البداية.
  - مراقبة مؤشر `governor.is_investigation_exhausted()` والتدخل اللحظي بحقن موجه مباشر: `"SENTINEL DIRECTIVE: Stop exploring. Apply immediate code patch to target file."` مما يمنع الوكيل من استنزاف التوكنز في قراءات لا نهائية.

### 23. `orchestrator/pipeline/dev_test_loop.py`
- **الدور الحالي:** ينفذ الحلقة التكرارية الأساسية لتطوير البرمجيات (Developer -> Preflight -> Tester -> Fix Loop).
- **المتغيرات والدوال:**
  - `DevTestLoop.run(task_description) -> dict`
  - إدارة عداد التكرارات `iteration`، تتبع نسبة نجاح الاختبارات، وإدارة حالات النجاح والفشل.
- **الاندماج المعرفي للعميل الرقابي:**
  - الكشف عن تكرار نفس خطأ الاختبار لأكثر من مرتين (Regression Loop) وتفعيل محرك `Self-Healing Hypothesis Generator` الذي يحلل الفرق في الكود ويقترح للوكيل زاوية تفكير جديدة وحلاً جذرياً.

### 24. `orchestrator/pipeline/full_pipeline.py`
- **الدور الحالي:** ينفذ خط الأنابيب البرمجي الكامل متعدد المراحل (Architect -> Developer -> Tester -> Independent Reviewer -> Documentation).
- **المتغيرات والدوال:**
  - `FullPipeline.run()`، وإدارة الانتقال بين المعالم (`MilestoneDAG`).
- **الاندماج المعرفي للعميل الرقابي:**
